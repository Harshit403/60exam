   113→- The Next.js Turbopack dev server gets OOM-killed when compiling the app
   114→- The LandingPage.tsx is 1307 lines - this is a very large component that may contribute to memory pressure
   115→- **Verification**: The code compiles and serves correctly (HTTP 200 confirmed via curl), but the Turbopack process is killed after serving due to memory exhaustion
   116→- **Recommendation**: Split LandingPage.tsx into smaller sub-components (Hero, Features, Courses, Reviews, etc.) to reduce compilation memory
   117→- **Alternative**: Consider using webpack compiler instead of Turbopack by removing `--turbopack` flag (but Next.js 16 uses Turbopack by default)
   118→- **Workaround**: The server can start and serve pages for the first request, but may crash under sustained load
